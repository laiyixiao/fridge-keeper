# 冰箱管家（Fridge Keeper）设计文档

**日期**：2026-08-17
**状态**：已评审待实现

## 1. 目标与范围

一个自用的网页应用，帮助管理家里冰箱中的食品，功能包括：

1. **食品管理**：录入、修改、删除食品，记录生产日期、保质期等信息。
2. **到期提醒**：食品临近保质期时主动推送提醒到微信；默认在到期前 30 天、7 天、3 天各提醒一次，也可在录入/修改单个食品时自定义提醒节点。
3. **推荐菜**：根据冰箱现有食材，调用 AI 生成推荐菜，用户可选"家常"或"减脂"偏好。

**明确不在范围内（YAGNI）**：多用户/登录系统、食品照片、条码扫描、库存数量精确计量、营养数据库。

## 2. 关键决策（来自需求澄清）

| 决策点 | 选择 |
|---|---|
| 形态 | 网页应用（PWA，可添加到主屏幕），移动端优先 |
| 使用者 | 单用户，免登录 |
| 提醒渠道 | Server酱（推送到微信）+ 页面内高亮 |
| 推送时间 | 每天中午 12:00（Asia/Shanghai），当天多条提醒合并为一条 |
| 推菜 AI | 阿里云百炼（DashScope / Qwen，OpenAI 兼容接口） |
| 部署 | 免费云：Next.js on Vercel + Neon 免费 Postgres |

## 3. 架构

```
浏览器 (Next.js 页面, PWA)
        │
        ▼
Next.js App (Vercel)
 ├─ 页面 (食品列表 / 录入 / 推菜 / 设置)
 ├─ API 路由 (增删改查、推菜、Cron 检查)
 └─ Vercel Cron (每天 12:00 Asia/Shanghai)
        │              │
        ▼              ▼
  Postgres (Neon)   外部服务
                    ├─ Server酱 (推微信)
                    └─ 阿里云百炼 (Qwen 推菜)
```

**技术栈**
- 框架：Next.js（App Router）+ TypeScript
- 样式：Tailwind CSS
- 数据库：Neon 免费 Postgres
- ORM：Prisma
- 定时任务：Vercel Cron
- 外部服务：Server酱（微信推送）、阿里云百炼（推菜 AI）

**模块划分（每个单元职责单一、可独立测试）**
- `lib/expiry`：到期日计算、"今天该提醒哪些食品"的判定逻辑（纯函数，最易测试）。
- `lib/notify`：Server酱推送封装（组装消息、发送、失败处理）。
- `lib/ai`：推菜 AI 封装，接口与具体模型解耦，以后可替换。
- `app/api/*`：HTTP 接口层，负责校验、编排、返回。
- `app/(pages)/*`：前端页面与组件。

**安全**
- 单用户免登录，但后端写操作 API 用环境变量中的密钥做简单保护，避免接口被他人调用。
- Cron 接口校验 `CRON_SECRET`（Vercel Cron 请求头携带），拒绝外部直接调用。

## 4. 数据模型

### food_item（食品表）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | PK | 主键 |
| name | text | 名称（如"牛奶"） |
| category | text? | 分类（乳制品/蔬菜/肉类/…，可选） |
| quantity | text? | 数量+单位（如"2 盒"，纯文本） |
| storage | enum | 存放位置：冷藏 / 冷冻 / 常温 |
| production_date | date? | 生产日期 |
| shelf_life_days | int? | 保质期天数 |
| expiry_date | date | 到期日（最终生效值） |
| reminder_days | int[] | 提醒节点，如 `[30,7,3]`；缺省继承全局默认 |
| created_at | timestamptz | 创建时间 |
| updated_at | timestamptz | 更新时间 |

**到期日规则**：录入时可填「生产日期 + 保质期天数」自动计算，或直接填「到期日」，二者至少填其一，最终统一落到 `expiry_date`。

### reminder_log（提醒记录表）
用于防止同一提醒节点重复发送。
| 字段 | 类型 | 说明 |
|---|---|---|
| id | PK | 主键 |
| food_item_id | FK | 关联食品 |
| reminder_day | int | 触发的节点（如 7）；过期提醒用特殊值 `-1` |
| sent_at | timestamptz | 发送时间 |

### settings（全局设置，单行）
| 字段 | 说明 |
|---|---|
| default_reminder_days | 全局默认提醒节点，默认 `[30,7,3]` |
| serverchan_sendkey | Server酱 SendKey |
| push_hour | 推送小时，默认 12 |

## 5. 提醒逻辑

**默认节点**：到期前 30 天、7 天、3 天各一次（全局默认，可在设置改；单个食品可覆盖）。

**每天定时任务流程**（Vercel Cron，每天 12:00 Asia/Shanghai 触发内部 API）：
1. 取出所有食品，计算每样"距到期天数" `daysLeft = expiry_date - today`。
2. 对每样食品，遍历其提醒节点 `d`：若 `daysLeft <= d` 且该 `(food, d)` 未在 `reminder_log` 中，则视为命中待发。
3. 已过期食品（`daysLeft < 0`）归为"已过期"提醒（同样用 log 去重）。
4. 将当天所有命中项**按剩余天数分组、合并为一条消息**，通过 Server酱推送。
5. 推送成功后，为每个命中项写入 `reminder_log`。

**为什么用 `<=` 而非 `==`**：即使某天 Cron 未成功执行（漏跑），第二天仍能补发，不会错过提醒；`reminder_log` 保证每个节点只发一次。

**消息示例**（合并为一条）：
```
🧊 冰箱提醒（8月17日）
⚠️ 还有 3 天到期：牛奶(2盒)、菠菜
⏳ 还有 7 天到期：鸡蛋
❌ 已过期：豆腐
```

**页面内提醒**：打开网页时，即将到期（默认 7 天内）和已过期的食品在列表顶部高亮，不依赖推送。

## 6. 推菜功能

**流程**：
1. 用户在推菜页选择偏好：**家常** 或 **减脂**。
2. 后端取出冰箱现有食材，**将快到期食材排在前面**（引导优先消耗）。
3. 组装 prompt 调用阿里云百炼（Qwen），返回 2-3 道菜，每道含：菜名、用到的食材、简要步骤。
4. 若为"减脂"，prompt 增加约束：少油、优先高蛋白低碳水，并给出大致热量估计。
5. 结果中标注"这道菜能用掉即将过期的 XX"，将推菜与保质期联动。

`lib/ai` 将 AI 调用封装为可替换模块，模型/供应商变更只改一处。

## 7. 页面结构（移动端优先）

- **首页 / 食品列表**：卡片列出所有食品，按到期日排序；快到期红色高亮、已过期灰色标记；顶部"即将到期"提醒条。
- **录入 / 编辑页**：表单——名称、分类、数量、存放位置、生产日期+保质期（或直接填到期日）、提醒节点。
- **推菜页**：选家常/减脂 → 生成 → 展示推荐菜。
- **设置页**：全局默认提醒节点、Server酱 SendKey、推送时间。
- 底部标签栏在页面间切换。

## 8. 错误处理

- **Server酱推送失败**：记录日志，**不写入** `reminder_log`，使下次 Cron 重试补发，避免丢提醒。
- **百炼 AI 失败/超时**：页面提示"推菜暂时不可用，请稍后再试"，不影响其他功能。
- **表单校验**：到期日 / 保质期二选一必填；日期格式校验；保质期天数为正整数。
- **数据库错误**：接口返回明确错误码，前端友好提示。

## 9. 测试策略（TDD）

**核心逻辑单元测试（优先，纯函数最易测）**
- 到期日计算（生产日期 + 保质期天数）。
- "今天该提醒哪些食品"的判定（含漏跑补发、去重、过期归类）。
- 消息合并组装（分组、格式）。

**API 集成测试**
- 食品增删改查。
- 推菜接口（AI 与 Server酱以 mock 替代）。

**手动验收**
- 真实发一条 Server酱到微信确认到达。
- 真实调一次百炼确认推菜效果。
